# Project skeleton

> Source: 08_MOD_CREATION_TOOLKIT.md (compiled 2026-07-29, verified against Project Zomboid 42.20). Imported 2026-09-29. Confidence tags in the text are the original author's.

**What you build:** the versioned B42 project scaffold every other recipe drops files into.

**Files + placement.** Develop under `Zomboid/Workshop/`. The game-readable mod root needs a mandatory `common/` folder plus a `42/` build-version folder that holds `mod.info`, `poster.png`, and the build-specific `media/`. [CONFIRMED -- pzwiki *Mod structure* rev 1443271; doc 01 sec 3-4]

```
Zomboid/Workshop/
  MyModItem/                       <- dev/repo root (only Contents/ is uploaded)
    preview.png                    <- Steam Workshop preview, 256x256
    workshop.txt                   <- auto-generated by the in-game uploader; do NOT hand-write
    Contents/
      mods/
        MyMod/                     <- the mod root the game reads
          common/                  <- MANDATORY (even if empty). Bulky shared assets: models, textures
            media/
          42/                      <- build-version folder for game 42.0+
            mod.info               <- manifest (keep it here, not in common)
            poster.png             <- in-menu preview
            media/
              registries.lua       <- top of media/, beside lua/ and scripts/ (NOT inside them)
              scripts/             <- .txt script files (items, recipes, entities, fluids, sounds, vehicles)
              lua/
                shared/            <- loaded first; data tables, translations under shared/Translate/
                client/            <- loaded after shared; UI, context menus, timed actions
                server/            <- loaded only when a world starts; authoritative logic
              textures/            <- icons (Item_*.png), UI art
```

Version-folder naming strips the minor version: a folder `42.1.5` resolves to `42.1`; a bare `42` = `42.0`. The game loads `common/` first, then the closest version folder to the running build, which overwrites same-path files. A B41-only fallback is the *old flat* `media/` at the mod root -- there is **no `41/` folder**. [CONFIRMED -- doc 01 sec 4]

**mod.info -- minimal (all keys lowercase, no hidden `.txt` extension).** [CONFIRMED -- pzwiki *Mod.info* rev 1363935; doc 01 sec 5]

```
name=My Amazing Mod
id=myAmazingModID
description=Adds one item and one recipe.
poster=poster.png
icon=icon.png
author=yourhandle
require=otherModID
```

| Field | Meaning |
|-------|---------|
| `id` | Unique mod identifier; goes in a server's `Mods=` line. NOT the Steam Workshop ID. `id`+`name` are the minimum. CONFIRMED |
| `name` / `description` | Shown in the in-game mods list. CONFIRMED |
| `poster` / `icon` | PNG filenames beside `mod.info`. CONFIRMED |
| `author` | Singular `author` (not `authors`). CONFIRMED |
| `require` | Comma-separated dependency mod IDs; load order must place them first. CONFIRMED |
| `versionMin` / `versionMax` | Min/max game version shown in the mod manager. Existence CONFIRMED; exact spelling LIKELY (verify in ScriptsDocs root-modinfo or a real mod.info). |
| `pack` / `tiledef` | Tile/asset-pack grouping + custom tiledef declarations for map mods. LIKELY (see sec 22). |

**registries.lua -- new in 42.13, loaded before ALL other Lua and scripts.** Declare every custom identifier here or downstream scripts won't find it. Path must be exactly `media/registries.lua`. [CONFIRMED -- pzwiki *Registries* rev 1392729; doc 01 sec 6]

```lua
-- media/registries.lua : the 11 registerable identifier types
CharacterTrait.register("mymod:nimblefingers")
CharacterProfession.register("mymod:thief")
ItemTag.register("mymod:bobbypin")
Brochure.register("mymod:Village")
Flier.register("mymod:BirdMilk")
ItemBodyLocation.register("mymod:MiddleFinger")
ItemType.register("mymod:gamedev")
MoodleType.register("mymod:Focused")
WeaponCategory.register("mymod:birb")
Newspaper.register("mymod:BirdNews", List.of("BirdKnews_July30", "BirdKnews_July2"))

local item_key = ItemKey.new("bullets_666", ItemType.NORMAL)
AmmoType.register("mymod:duck_bullets", item_key)

-- store a reference if Lua needs it later (scripts use the STRING id, not this variable)
MyMod = MyMod or {}
MyMod.MY_TAG = ItemTag.register("mymod:my_tag")
```

The 11 registerable types: `CharacterTrait`, `CharacterProfession`, `ItemTag`, `Brochure`, `Flier`, `ItemBodyLocation`, `ItemType`, `MoodleType`, `WeaponCategory`, `Newspaper`, `AmmoType`. In **scripts** you reference the string ID (e.g. `Tags = mymod:bobbypin`); the returned Lua object is only for Lua-API calls (`item:hasTag(MyMod.MY_TAG)`). [CONFIRMED]

**Gotchas.** `common/` is mandatory or the mod is invisible. Don't stay subscribed to your own Workshop copy while developing (two same-ID copies clash and silently swallow edits). Name the file `mod.info` lowercase. Enable `-debug` and read `Zomboid/console.txt` to catch load errors.
